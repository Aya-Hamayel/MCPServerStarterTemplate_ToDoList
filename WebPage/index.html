Model Context Protocol · Coursework Project

Give your AI assistant
a real imaginary to-do list.

The To-Do List MCP Server exposes a small, well-defined set of tools — add, list, complete, delete, search — so an AI model can manage a person's tasks directly, validated and running entirely on their own machine.

View repo → See the demo story
01

Why this exists

The problem

Students, developers, and office workers need a simple way to track daily work — but most task tools live behind a UI an AI assistant can't touch, and require accounts or paid services just to get started.

The approach

Expose the task list as a set of clear MCP tools an AI can call directly. No paid APIs, no external services — the server runs locally and stores tasks in a plain JSON file.

Architecture

validate schemas/
→
register tools/
→
persist lib/tasks.ts

Every tool input is checked against a Zod schema before it reaches storage. Tasks are read from and written to data/todos.json, validated one entry at a time so a single malformed record can't wipe the rest of the list.

03

Tool inventory

Tool Description Inputs Priority
add_task Create a new task in the to-do list. text: string P0
list_tasks Return tasks currently stored in the to-do list. text?: string, limit?: number P0
complete_task Mark an existing task as completed using its task ID. taskId: string P0
delete_task Remove an existing task using its task ID. taskId: number P1
search_tasks Search stored tasks using a keyword. query: string P1
04

Demo day story

  1. add_task

    The user asks the assistant to add a task called "Finish the Linux assignment." The model calls add_task and returns the new task's ID.

  2. list_tasks

    The user asks to see all current tasks. The model calls list_tasks and displays what's on the list.

  3. complete_task

    The user says the Linux assignment is done. The model calls complete_task with that task's ID and confirms it's marked complete.

Out of scope

  • User authentication and multiple user accounts
  • Mobile or graphical user interface
  • Notifications, reminders, or calendar integration
  • Cloud database synchronization
  • Paid APIs or external online services
